# 待测试

## v1.3.10 FOR 节点拖动与导演台任务续做

- 拖动 FOR 文件夹循环节点的面板空白处或说明区域，可像普通节点一样移动。检查选文件夹、复选框和循环按钮仍可操作，鼠标滚轮仍在面板内滚动。
- 在导演台提交包含多个场景改动的指令。模型输出截断或已经修改场景但步骤清单未完时，会自动续做一次。核对完成过的动作不重复，剩余步骤可继续执行，连续截断时显示未完成提示。

## v1.3.8 直接安装所选版本

- 在「检查与修复」检查更新，选择正式版本，点击「安装所选版本」。同一操作完成下载、校验和安装。安装结束后窗口显示已安装的版本，关闭并再次打开时启用，项目与模型配置继续使用原数据目录。
- 测试安装失败时入口保留、导入 ZIP、回退确认和有空格的中文路径。旧版无法完成更新时可解压新版，在存储设置选择旧数据目录。
- 整合包内的开源说明指向对应版本的 GitHub 发布页。验收包中无独立源码 ZIP，发布页的 Source code 可获取对应源码。

## v1.3.7 RunningHub 多模型

- 在启动器或浏览器的「模型配置」选择 RunningHub 标准模型，点击「检测渠道并读取模型」。应从官方英文文档实时读取标准模型，按图片、视频、3D、音频及其他分组，并单独显示账户密钥检查结果。
- 在图片、视频分组中逐个添加模型，检查添加后各模型进入对应生成列表。保存并重启后，多个模型和原有默认选择应保留。已有 GPT Image 2 配置可继续用，也可从目录重新读取参数。
- 使用 Seedream 文生图、GPT Image 2 图生图、Vidu 图生视频、Veo 文生视频验证各模型的提交地址、参考图与必填参数。视频任务须保留任务编号，成功后写入本机素材。超出画布输入能力的模型应提示具体缺少的参数。
- 用企业级共享密钥验收实际账户权限及生成。3D 与音频目录可浏览。文字与白模导演的文字模型仍通过 OpenAI 兼容渠道配置。

## v1.3.5 模型目录与 RunningHub 图生图

- 读取渠道目录时先用返回的输出能力分类，再识别常见模型名。识别成功的模型自动加入各功能下拉框，无法识别的保留为待手动分类。明确不支持工具调用的文字模型不会加入白模候选。
- 导入采用追加方式。已有渠道、手动分类和默认模型不被覆盖，同名模型按渠道区分。浏览器刷新模型设置保留仍可用的工作区选择，明确修改某项启动器默认值时应用该项新默认。

- 启动器和浏览器的模型配置新增「RunningHub 标准模型」类型。可填写全球站根地址或 GPT Image 2 经济版图生图的完整提交地址，保存时统一记录为官方根地址。
- 内置 `rhart-image-g-2/image-to-image`，用账户接口检查密钥。文字模型目录仍通过独立的 OpenAI 兼容渠道配置。
- 画布及生图工作台通过参考图发起异步生成。保存服务商任务编号，重启后恢复查询；提交状态不明确时提示先核对任务，避免再次提交。产物链接在成功后下载到数据目录。
- 账户检查、提交、轮询、重复任务编号、恢复及落盘以模拟接口验证。使用用户的企业级共享密钥和余额实际生成仍需验收。

## v1.3.4 稳定性

- 在线与离线安装在独立程序目录准备。新版启动器就绪才切换；切换前中断可继续使用原程序。发行包根目录提供“恢复原启动器.cmd”。
- 下载使用同一校验值关联断点，并对最终文件重新核对 SHA-256。下载、解压、安装分别检查所在盘的空间。可清理下载缓存和闲置的程序版本，保留当前程序、原启动入口和已校验待安装包。
- 画布 ZIP 导出磁盘素材、完整白模场景及其内嵌模型和动作。导入在目标数据目录重新保存；原电脑的文件夹授权需重选，未完成的生成任务需按新工作区处理。
- 画布单窗口编辑，其他窗口可查看循环进度；保存反馈区分保存中、成功与失败。循环步骤提交前在本机登记，只有明确重试才新建提交。
- 本机素材使用流式落盘，文件夹循环显示导入进度并可取消。Windows 发布流程要求先通过隔离工作区迁移及实际安装、升级、中断、回退验收。
- 旧启动器首次更新仍使用旧版自身的安装方式。若需要直接启用独立版本安装机制，可完整解压新版，并在“存储设置”选择原数据目录。

## v1.3.3 更新与进程管理

- 更新器使用 Electron Chromium 网络，跟随 Windows 系统代理／PAC 和系统证书；检查、校验文件和整包下载使用同一通道。失败显示中文原因及离线导入提示，重试清除旧错误。
- 分页读取本仓库全部正式发行版，过滤草稿与预发行，展示版本说明，明确选择目标版本后才能下载；支持升级、重装当前版本和回退。
- 待安装状态保存目标版本和安装意图，重新打开仍可安装；其他版本下载失败时保留并准确显示先前已校验的目标。
- 在线回退和离线导入旧包均在实际安装前提示：程序回退保留数据，但不会把新版数据格式转换回旧格式。取消回退不会停止现有服务。
- 首页与“检查与修复”新增强制停止；显示本启动器管理的服务名称和 PID。可取消卡住的启动并结束后台进程树，保留无关进程，随后重新启动。
- 已通过 22 项单元测试，以及真实 Electron 界面的代理请求、断网提示、版本列表、回退包下载／重启恢复、取消回退和三个真实服务停止／重启。Windows 原生构建额外执行进程树终止测试。Windows 实际系统代理、安装和回退仍需实机验收。

## v1.3.2 新增验收

- 导演台 H.264 视频附件由本机 FFmpeg 抽取九宫格画面，不再依赖浏览器解码器；视频仅在发送消息时作为抽帧图交给视觉模型，支持 1 GB 以内视频。损坏视频提示原因，处理结束清理临时文件。
- 导演台 MCP 已验证放置白模道具、读取场景和导出本机项目文件；文件保存限定数据目录，越界路径被拒绝。
- 小尺寸循环节点可在内部滚动查看错误和重试操作，不会把文字压缩隐藏。
- FOR 文件夹循环通过启动器原生对话框选目录，支持子目录与自然文件名排序；逐文件执行相连工作流，每步一份结果。支持文本、图片、视频、音频、全景、生成配置；首版不嵌套循环，不自动操作导演台或组。
- 循环保存输入快照、模板、步骤和结果，暂停时等待当前任务完成。重新打开后手动继续，已有服务器任务只查询，不自动重发；提交状态未确认时停止并要求用户核对后重试。输入文件变动或路径失效会停止。
- 画布 MCP `canvas-studio-canvas` 与导演台 MCP `canvas-studio-director` 随包运行，支持 stdio 与 Streamable HTTP；多个工作区须明确指定。MCP 面板提供独立配置，导演台底部提供专属配置入口，无需原项目插件或 Codex CLI。
- 启动器 Skill 管理支持新建、编辑、Markdown／文本导入、导出和删除，存储在本机数据库；文字节点和文字生成配置可选择最多五个 Skill。MCP 支持管理用户 Skill、选择渠道和 Skill 生成 AI 文字。
- 已通过 15 项启动器单元测试、原生 Electron Skill 管理与重启测试、通用 MCP HTTP＋stdio 测试、两个文件各执行两步及暂停刷新恢复、Skill 请求注入、H.264 8 位 420／10 位 444 样例及实际附件 UI 测试。原导演台场景、模型、动作、截图／MP4 回传和新浏览器恢复回归通过。
- 仍需在 Windows 实机确认原生目录选择、H.264 原始问题文件、不同外部 MCP 客户端的配置界面和真实模型 API。没有收到用户原始视频，本次使用编码样例验证。

## Windows 本地工作台整合版

- 首页指定 Edge、Chrome、Firefox 或自选浏览器程序，启动与打开时自动保存，重启保留；不同自选程序使用独立资料目录。
- GitHub Releases 更新框架：启动时或手动检查、下载进度、SHA-256 与文件清单校验、重启恢复待安装包、安装前再校验；保留离线导入。配套公开源码与 Windows 构建发布工作流。
- 中文启动器：一键启动／停止、模型配置、存储设置、日志、检查、发行包导入和关于。
- 固定本机身份，无账号登录；项目和任务通过本地 SQLite 保存，素材写入数据目录。
- 启动器和浏览器共用模型配置；系统加密保护 API Key，浏览器通过本机代理调用。
- 支持多个独立渠道，分别测试连接、管理模型和加密密钥；白模、文字、图片、视频可分别指定默认渠道及模型，画布与导演台内也能切换。同名模型按渠道区分，已有视频任务仍从原渠道查询，保留上一版单渠道设置。
- CozyClay 替换导演台，完整项目文件保存导入资产，截图和动画回传画布并加入素材库。
- 移除滚动营销、推广入口、主界面 GitHub 图标和版本号；许可与对应源码保留。
- 已做 Linux 构建、后端和启动器测试及浏览器联调；Windows 实机、DPAPI、真实 AI 服务和更新应用流程尚待验收。
